# Передача проекта

Состояние на 5 октября 2026 года. Разработка и все попытки входа в сервисы остановлены по просьбе владельца. Использовать только корпоративные аккаунты и ресурсы. Если профиль Chrome или аккаунт не удаётся уверенно определить как корпоративный, попросить владельца открыть ссылку вручную в корпоративном профиле.

## Назначение и правила

Сервис должен работать для **Verona Home + WallPanels** через HighLevel, Telegram Bot, Supabase, корпоративный GitHub и Railway. HighLevel используется только для чтения. Режим испытаний (`TEST_MODE=true`) направляет уведомления только Дмитрию. Переход в рабочий режим требует отдельного разрешения владельца.

Нужно отслеживать **все клиентские каналы сообщений**: SMS, Email, WhatsApp, Instagram, Facebook, Live Chat/WebChat, GMB и новые типы входящих сообщений, которые вернёт HighLevel. Выгрузка без параметра `channel` получает сообщения кроме Email; отдельная выгрузка с `channel=Email` получает Email. Звонки не запускают таймер без реального входящего текстового сообщения. Ожидание закрывает только настоящий исходящий ответ сотрудника, а не сообщение из workflow, campaign, API, бота или другого автоматического источника. Пороговые уведомления: **60/90/120 минут** в рабочем режиме и **2/4/5 минут** в режиме испытаний.

## Сделано локально

- Проект распакован в эту папку, зависимости установлены, Git создан с `main` и корпоративным `origin`. Файлы проекта пока не закоммичены и не отправлены.
- `.env.local` создан из разрешённого владельцем документа, права файла ограничены; он игнорируется Git. Секреты в этом файле не приводятся здесь.
- Реализованы чтение и раздельная выгрузка каналов HighLevel, нормализация канала, исключение звонков, хранение состояния ожидания и единая логика SLA. Неизвестный тип с текстом или вложением сохраняется как `Other:<тип>`.
- Для определения ответа сотрудника используется известный HighLevel `userId` и источник `app`, который наблюдался в реальной выгрузке Verona. Неизвестные источники не закрывают SLA.
- Добавлены маршрутизация по владельцу открытой Opportunity, затем Conversation, затем Contact; сопоставление сотрудников по точному имени; запасная отправка руководителю и администратору; Telegram `/start`, `/status`, `/test_alert`; `/health`; миграция БД; инструкции запуска. Схема обновлена отдельными таблицами `telegram_users`, `sla_incidents`, `assignment_mismatches` и `system_logs`.
- Реальные запросы **GET** к Verona HighLevel подтвердили доступ к локации, 17 пользователей, экспорт SMS и Email, а также наличие звонков в выгрузке без `channel`. Ручные исходящие SMS и Email имели `source=app`; workflow-сообщения также имели `userId`, поэтому одного `userId` недостаточно для распознавания ответа человека. WhatsApp, Instagram, Facebook и WebChat в доступном образце не встретились. Telegram Bot API ответил на проверку токена.
- TypeScript-проверка, 4 теста и сборка прошли после последних изменений.

## Не завершено и ограничения

- Миграция **не применена** в корпоративном Supabase. Проверка показала, что таблицы ещё отсутствуют. Вход Supabase CLI не завершился; последний сеанс отменён. Вкладка корпоративного Chrome была открыта владельцем, но инструменту не была доступна. Никаких дальнейших попыток входа по просьбе владельца не делать в этом сеансе.
- GitHub: коммита и отправки нет. Попытка входа GitHub CLI с сохранением токена без шифрования была отклонена автоматической проверкой. Личные аккаунты и хранилища учётных данных не использовать.
- Railway: проект и сервис не созданы, переменные не загружены, размещения нет. Не использовать личный профиль или личные проекты.
- Telegram `/start`, `/status`, `/test_alert` и реальный путь уведомлений пока нельзя проверить до создания таблиц. Ручной ответ по Email и сообщения WhatsApp/Instagram/Facebook/WebChat отсутствовали в доступном образце HighLevel; их поведение нужно проверить на реальных примерах. Источник настоящего ручного Email-ответа пока не подтверждён.
- Токен WallPanels не был указан, поэтому WallPanels остаётся отключённым до его получения. Пример настоящей ссылки на Conversation также отсутствует; кнопка открытия переписки требует шаблон, полученный из реальной ссылки.

## Следующие шаги для другого корпоративного Codex-аккаунта

1. Проверить локальные файлы, выполнить `npm run typecheck`, `npm test`, `npm run build`; при необходимости исправить найденное.
2. После подтверждённого корпоративного входа применить миграцию к **точному** корпоративному проекту Supabase, проверить таблицы и ограничения доступа.
3. Запустить сервис локально в `TEST_MODE=true`, зарегистрировать Дмитрия через `/start`, проверить `/status` и `/test_alert`, затем реальный входящий запрос Verona и остановку уведомлений после ручного ответа. Отдельно проверить ручной Email и остальные доступные каналы.
4. Получить у владельца недостающий токен WallPanels и одну настоящую ссылку Conversation; подключить WallPanels и повторить проверки.
5. Перед отправкой GitHub проверить индекс и отсутствие секретов, использовать только корпоративную учётную запись. Затем подключить Railway к корпоративному GitHub, задать переменные и проверить `/health` в `TEST_MODE=true`. Переход на 60/90/120 минут в рабочем режиме делать только после отдельного согласия владельца.
